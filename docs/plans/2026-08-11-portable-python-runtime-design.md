## 状态

已确认。本文替代 `2026-08-03-ts-local-auto-update-design.md` 中关于本地 Python、
系统 Git、候选版本验证、多版本缓存和回退的设计。

## 目标

为 Windows x64 提供可复制的 HTFA 目录。目标电脑无需预装 Python、pip、Git
或编译工具；断网时可以直接运行，联网时每次启动检查 `BichengNiu/Ts` 的
`main` 最新提交并在需要时更新。

## 边界

- 内置 CPython 3.13.4 和 HTFA 的全部固定依赖。
- `main` 最新提交就是 Ts 最新版，不使用 Release 或标签。
- 只在线更新 Ts；HTFA、Python 和其他依赖不自动更新。
- 不执行 Ts 接口验证或独立进程烟测。
- 不使用后台更新、定时任务、手动更新脚本或多版本缓存。
- Docker 配置不属于本次 Windows 自包含交付范围。

## 发布布局

```text
HTFA/
├─ runtime/                  # CPython 3.13.4、固定依赖和当前 Ts
├─ dashboard/
├─ scripts/
├─ data/
├─ app.py
├─ start.bat
└─ runtime-manifest.json     # 运行时版本和构建信息
```

`.venv` 继续只用于开发且不进入发布包。发布版 `start.bat` 只调用
`runtime\python.exe`，不得探测或使用系统 Python。

## 启动与更新流程

1. `start.bat` 检查 `runtime\python.exe` 是否存在并调用自包含启动器。
2. 启动器通过 GitHub HTTPS API 查询 `BichengNiu/Ts` 的 `main` HEAD，查询使用
   短超时。
3. HEAD 与本地记录一致时，直接使用当前 Ts 启动 HTFA。
4. 无网络、查询超时或下载失败时，不修改当前 Ts，直接启动 HTFA。
5. HEAD 不一致时，按该提交下载 GitHub ZIP，提取 Ts 运行文件并更新本地提交记录。
6. 下载和替换成功后，本次启动使用新 Ts。

更新是前台启动步骤，不创建后台进程。发现新版本时，启动时间包括下载时间；没有
新版本或离线时，只承担一次短时 HEAD 查询。

## 最低下载安全措施

虽然不验证 Ts 的行为或接口，更新流程仍保留以下文件系统安全约束：

- 仅允许 GitHub HTTPS API、固定仓库 `BichengNiu/Ts` 和固定分支 `main`。
- HEAD 必须是完整提交哈希；ZIP 必须对应这个固定提交，而非再次解析移动分支。
- 限制下载和解压体积。
- 拒绝绝对路径、`..`、符号链接和其他 ZIP 路径越界。
- 只提取 Ts 运行所需的允许文件。
- 在同一文件系统中先写临时目录，完整下载和解压后再替换当前 Ts；下载失败不得留下
  半更新目录。

这些措施只保护下载和文件替换过程，不判断新 Ts 是否正确。

## 已接受的风险

- `main` 中的代码一经下载就会用于本次启动。
- 新提交存在语法错误、缺少接口或行为回归时，HTFA 可能启动失败或运行异常。
- 按已确认边界，不增加候选版本烟测、接口验证或自动回退。
- 恢复方式是重新解压已发布的完整离线包，或在开发端修复 Ts `main` 后再次启动更新。

## 依赖与构建

- 构建输入使用官方 Windows x64 CPython 3.13.4 嵌入式运行时。
- 运行依赖必须锁定为 Python 3.13 / Windows x64 的确切版本；`requirements.txt`
  继续表达支持范围，单独的锁定文件表达发布包的精确解析结果。
- 构建阶段只接受二进制 wheel，禁止目标电脑编译或安装依赖。
- 发布目录不得包含 `.venv`、pip 下载缓存、测试缓存、凭据或构建临时文件。
- `runtime-manifest.json` 至少记录 Python 版本、平台、依赖锁摘要、内置 Ts 提交和构建时间。

## 错误提示

- 缺少或无法启动内置 Python：明确报告发布包损坏，不建议安装系统 Python。
- 网络不可用：显示简短信息并继续使用当前 Ts。
- 下载或安全提取失败：显示失败原因并继续使用当前 Ts。
- 新 Ts 替换成功但 HTFA 随后失败：保留真实异常，不把它误报为 Python 环境缺失。

## 验收标准

1. 在未安装 Python、pip 和 Git 的 Windows x64 环境中，断网启动成功。
2. 将完整发布目录复制到不同用户和不同磁盘后启动成功，不含创建电脑的绝对路径。
3. HEAD 未变化时不重复下载 Ts。
4. HEAD 变化时下载并使用对应提交，且本地提交记录同步更新。
5. DNS 失败、超时、HTTP 错误和下载中断时仍使用当前 Ts 启动。
6. 恶意或异常 ZIP 路径不能写出更新暂存目录。
7. 更新中断不会留下部分覆盖的 Ts。
8. 使用发布版内置 Python 完成编译检查、自动化测试和 Streamlit 页面烟测。
9. 发布包经过缓存清理、文件清单检查和跨目录复制验证。
