# 迁移采用直接切换且不保留兼容路径

**Status:** accepted

每个迁移阶段先建立可验证的逻辑 seam，再一次性迁移全部调用方、删除旧实现并执行零遗留扫描。迁移不保留旧 import、旧 API、alias、wrapper、双读/双写、并行新旧路径、feature flag 或运行时 fallback；这些机制会使旧边界继续可用，无法证明迁移已经完成。

**Considered Options:** 长期保留兼容层；新旧实现并行并以开关切换；seam 建立后直接切换并删除旧实现。选择最后一种，以便每个阶段都有明确唯一事实实现和可审计的完成条件。

**Consequences:** 阶段测试失败时必须修复新 seam，不能借助旧路径恢复；数据发布失败回滚、解析失败清空和输入 fail-closed 等产品安全行为继续保留，因为它们保护数据正确性而不是提供架构兼容。
