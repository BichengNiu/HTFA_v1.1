# 能源保供采用数据、处理计算和显示三层架构

**Status:** accepted

能源保供继续遵循 ADR-0006 的模块化单体约定，在同一进程内划分 `data`、
`processing`、`ui` 三层。共享的 `contracts` 仅保存类型与来源字段定义。
不引入 HTTP 服务、独立数据库、消息队列或额外部署单元。

依赖方向为 `ui → processing → data`：显示层调用业务服务，业务服务调用数据访问
接口；数据层不引用计算或页面代码。计算层不引用 Streamlit、Matplotlib、DuckDB
执行接口或网络传输库。数据查询中的事务、参数绑定、分页完整性及来源记录验证仍由
数据层负责；统计口径、日期选择和业务补全由计算层负责。

资产目录和审计材料不再通过导入副作用或 `importlib.reload` 更新。维护作业显式构建
目录并保存，页面仅消费发布快照。导入任意能源模块不得访问数据库或网络。
Streamlit 缓存属于显示适配，缓存身份包含物理数据库身份及数据版本，避免候选库串用。

迁移遵循 ADR-0008，调用方一次性切换，不保留旧模块别名。数据回滚、来源失败隔离、
只读展示和数据库/Excel 成对发布仍是必须保留的产品行为。

**Consequences:** `htfa/jobs/energy_supply/` 继续编排采集与发布；Excel 数据源适配器
复用计算层的月度指标服务。三层依赖、循环依赖、导入安全及事务隔离由自动化测试约束。
