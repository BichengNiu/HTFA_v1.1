# 开发协作与文档约束

- 根目录 `AGENTS.md` 定义执行、测试、提交和推送规则；`CONTEXT.md` 定义领域词汇。修改前阅读相关现行约束，沿用领域术语。
- `docs/` 只维护当前仍适用的架构、模型、数据、运行和协作约束。规则变化时改写对应文档，不追加按日期累积的历史章节。
- 不在 `docs/` 保存实施计划、调研过程、修复经过、更新日志、测试成绩、数据截止日期清单或完成情况；历史从 Git 查阅，任务与规格由 GitHub Issues 跟踪。
- 文档只描述已经生效的规则，不将提议中的目录或接口当作现状。约束调整时同步调用方、说明和相关测试，删除失效引用，不保留历史入口。
- GitHub Issues 的标签角色为：`needs-triage` 待评估、`needs-info` 待补信息、`ready-for-agent` 可由代理执行、`ready-for-human` 需人工处理、`wontfix` 不处理。PR 不作为需求入口，代码直接按仓库规则提交到 `main`。
- 使用仓库连接或 CLI 读取相关 issue、评论和标签；创建、评论、分配或关闭 issue 等对外写入仍须符合当前任务授权，不能因文档存在就自动发布。
- 将有效输入校验、统计假设、工作簿协议、下载安全、认证及失败回滚视为产品行为，不得为了缩短代码移除。
- 代码或文档修改只提交本次目标文件，保留用户已有变动；运行相关测试即可，跨模块变更再扩大验证范围。清理、提交、推送及远端哈希核对遵循 `AGENTS.md`。
