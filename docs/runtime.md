# 运行与部署约束

- 使用根目录 `htfa.bat` 启动，`htfa.bat stop` 显式停止；`htfa.ps1` 统一管理启动、停止和运行时。日常执行及测试使用 `runtime/python.exe`。
- 仅在运行时缺失、损坏或依赖变化时执行 `htfa.bat setup-runtime`。构建须锁定依赖、验证下载、在候选运行时完成关键导入后替换；失败恢复旧运行时。
- 启动自动更新源码仅允许在本地 `main`、工作区干净且能快进时执行；失败显示警告并保留本地版本，不覆盖用户改动。
- Ts 从项目运行时加载；源码调整后须同步实际运行时副本。模块或依赖修改后停止旧进程并重启 `htfa.bat`，刷新页面不足以清除模块缓存。
- 浏览器与后端生命周期管理只匹配本次启动的独立浏览器用户目录，不得关闭用户其他窗口或标签页。
- Windows 写表使用 Excel COM；Linux 使用 `portable_sheet_writer.py` 消费相同来源载荷，保留工作表次序、其他工作表、有效零值、空值、单位和日期频率语义，原子写入并保持失败保护。
- 保活工作流仅负责打开和验证应用，不采集、写库、生成 Excel 或发布业务数据；不得将保活成功解释为数据更新成功。
- 保活验证必须实际渲染监测标题与指标，并持续正常显示；HTTP 200、前端空壳、休眠页、超时或页面异常均不算成功。遇到登录或私有访问限制时失败，不绕过认证。
- 保活空提交失败时仍可尝试唤醒，但作业须保留失败状态。失败截图不得附带 HTML、Cookie、浏览器存储或凭据；证书错误通过代理与 CA 配置处理，不关闭 TLS 验证。
- 数据库不由 Git 或 Git LFS 跟踪；云端部署须单独提供真实数据库并只读展示。仓库不再提供依赖 LFS 的云端每日采集发布工作流；本地维护入口继续可用。
- 精确依赖锁文件位于 `tooling/requirements/`，Docker 配置位于 `tooling/docker/`；本地与部署依赖保持一致。
